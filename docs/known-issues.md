| 范围 | 当前情况 | 展示时如何说明 / 后续处理 |
| --- | --- | --- |
| 部署 | 目前只在本机通过 Docker Compose 和 `127.0.0.1:3000` 演示，没有公网服务。 | 面试可现场运行或播放录屏；公开部署需另做 HTTPS、访问控制、资源与费用规划。 |
| 模型依赖 | `bge-m3` 首次下载和外部大模型调用依赖网络；首次分析还会重新计算并写入向量，响应可能较慢。 | 预先拉取模型、准备匿名数据，演示时说明正在检索；后续复用文档向量并记录耗时。 |

| 回答质量 | 模型可能把弱证据说得过强；输出中的 `[R]`、`[J]`、`[K]` 是回查入口，不自动证明结论正确。 | 逐条核对原文，把“当前简历没有证据”和“候选人不会”明确区分。 |
| 简历 API | CareerHub 目前直接返回 `Resume` 领域对象，字段中包含服务端文件路径。 | 公网部署前改成最小响应 DTO，只返回页面确需的字段，并复核权限。 |
| 仓库历史与凭据 | CareerHub 仓库曾为 Public，用户已在 GitHub 将其改为 Private。历史检查确认 `HEAD` 仍含旧密码，且本地 `origin/main` 指向同一提交；`requests.http` 也曾进入历史。Windows MySQL `root@localhost`、Compose MySQL `careerapp` 与两个 `root` 账号、两套 PostgreSQL `careerai`、两套 RabbitMQ `careerai` 均已轮换，现行 `.env` 和 IDEA 本机配置已同步；当前项目配置扫描未再发现旧公开密码。独立 PostgreSQL/RabbitMQ 容器的初始化环境变量仍显示已失效旧值，实际账号已使用新密码。CareerAI 目录尚不是 Git 仓库。 | 公开代码前清理或重新建立经审查的 Git 历史，复查其他敏感内容；改为 Private 或新增脱敏提交不会自动清除旧提交。 |
| 演示材料 | 本地浏览器流程已跑通，匿名结果截图已保存；页面顶部流程截图或短录屏可后续补充。 | 发布前再次确认不含 `.env`、Token、密码或真实个人资料。 |
